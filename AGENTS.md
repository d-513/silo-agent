# Silo Agent

Token-conserving multi-user agent. Each **Bot** is a durable container with a GUI. Architecture: `docs/Description.md`. UI: `DESIGN.md`.

How to build and run: [DEVELOPMENT.md](DEVELOPMENT.md).

Operator config: [docs/CONFIGURATION.md](docs/CONFIGURATION.md). Koanf **defaults → `silo.yaml` → `SILO_*` env**. Nested keys use `__` (`SILO_OPENROUTER__API_KEY` → `openrouter.api_key`). OpenRouter key is YAML/env, not Admin. Default model when unset: `openai/gpt-5.6-luna`.

## Shape

- **Control Plane (Go):** users, bots, secrets, **security engine** (`internal/security` — catalog of connector.action → title/fields/default; `*` for files/desktop; each secret is `secrets.<name>` not `secrets.get`; unknown MCP actions get a generic prompt), **HTTP MCP proxy** (`internal/mcpx` — streamable HTTP only; STDIO later), **agent loop** (OpenRouter/GPT), Docker lifecycle = create/start/stop/inspect only. Chat tools and Python `CallTool`/`GetSecret` share `authorizeAction`. Approval slip never dumps `args_json` (and redacts `desktop.type` text). `allow_once` is a valid vote. Connector tokens and extra headers stay on the CP. Reserved connector slugs: python, terminal, files, desktop, bot, secrets.
- **Worker (Go, inside Bot):** dials the CP. Local Unix-socket HTTP for Python tools (`get_secret`, `call`, desktop). `desktop.*` CallTool is a grant; the Worker runs look/click/type/key/scroll and strips type text before the RPC. Writes `/opt/silo/tools` from `SyncTools`. Tunnels VNC and a console PTY. Desktop is Openbox + Thunar + mousepad + iron wallpaper (`botimage/`). Dock: Files, Terminal, Editor, Chromium. `start.sh` is root only to chown mounts and supervise; the worker, X stack, console PTY, and dock apps run as user `silo` (uid 1000) with passwordless sudo. `start.sh` starts the worker before the X stack so the bot is online without waiting for x11vnc. ConnectRPC bidi does not send headers until the first `Send` — `Commands` must heartbeat immediately or the CP treats the worker as offline until the 10s ticker. x11vnc uses `-speeds lan` (localhost tunnel; skip the link-speed probe). Double-click text in Thunar opens the editor.
- **Python in the Bot:** `exec_python` + `silo_runtime` + generated `tools.*`. Not the orchestrator. `toolsgen` escapes `\` and `"` in generated docstrings — a description ending in `"` must not become `""""` and SyntaxError the whole package import. A nonzero exit from `exec_python`/terminal returns the captured output (the traceback) as the result; never just `exit status 1`. Desktop GUI is first-class `look` / `click` / `type` / `key` / `scroll` (1280×720 X11; worker uses `scrot`/`xdotool`) — that is how the model clicks the machine. The same actions are on `silo_runtime` (`type_text`, not `type`) so a secret can be typed without a chat `type` call. Playwright `silo_runtime.chrome_page()` is page screenshots, mutating displayed HTML, and automated scripts — not the live click loop. The worker opens `silo-chromium` when `exec_python` mentions Playwright / `chrome_page` (and `chrome_page` hits `/v1/chrome/ensure` again). Do not ship `chrome_eval` / raw CDP helpers or `pyautogui`. SYSTEM.md must forbid the model `xdotool`, `pyautogui`, `playwright install`, and `apt` for a GUI driver. Computer-use shots attach without `detail: high` (OpenAI-family tiling breaks xy).
- **Frontend:** pnpm + React + Tailwind. ConnectRPC + VNC websocket. Right-side “Needs you” panels (permission vote and MCP OAuth) share `NeedYouSlip` — do not hand-roll a second folio drawer. Files / Desktop / Console when the worker is down share `NeedMachine` — do not hand-roll a second offline well.

UI: 64px rail on every page (Bots, crest switcher, +). Bottom: wrench Admin (admins only), user Account stub, Sign out. Crest is a picked shape+color (`color * 8 + shape`), not hashed from the name. Bot tabs are `/bots/:id/{run,desktop,files,connectors,secrets,rules,container,settings}` labeled Chat, Desktop, Files, Connectors, Secrets, Rules, Container, Settings. Rules is Bot / Secrets / per-connector folio sections (Allow/Ask/Deny); detach and delete-secret prune rules so ghosts do not stay. Desktop is a dropdown: Desktop (hatch) or Console (`/bots/:id/console`, PTY in `/workspace` via the worker — not `podman exec`). Admin is `/admin/settings` (model + audit) and `/admin/connectors` (Connectors Library: HTTP MCP presets; default mode allow/ask/deny). Library rows are templates — attach copies them onto the Bot. A Bot may attach the same preset more than once (GitHub, GitHub 2); each copy has its own OAuth and `tools.<slug>`. Bots can also add a custom MCP. Presets seed from `internal/catalog` (`connectors.json` + images; insert-if-absent by `seed_key`). Catalog `guide` is display-only copy on the Bot add screen (not a textarea, not stored on the row). Clicking a library preset shows mark + large name, a bindery-edged “Before you add” well, and collapsed Advanced settings; submit is `CreateBotConnector` with `source_id`. The add form is shared between Admin library and Bot custom. OAuth opens `{public_url}/oauth/callback`. The SDK tries CIMD, then a pre-registered `client_id`/`client_secret` on the connector, then DCR — GitHub has no `registration_endpoint`, so the library/custom form takes an optional OAuth Client ID and Secret (callback `{public_url}/oauth/callback`). MCP HTTP URLs keep their query — `?codemode=false` is real server config (it turns off Cloudflare’s code-mode `execute` wrapper and exposes the full tool list) — but the query/fragment must be stripped from the request handed to OAuth `Authorize`, because the SDK derives the resource identity (`resource=`, `.well-known` lookups) from it and Cloudflare validates that strictly (its issuer is `https://mcp.cloudflare.com`). `internal/mcpx` is a thin wrapper over the official go-sdk client — do not hand-roll the transport (handshake, sessions, SSE, `Mcp-Method`/`Mcp-Name` headers all live in the SDK). Connect tries Streamable HTTP (± trailing slash), then the legacy 2024-11-05 HTTP+SSE transport (spec back-compat; Cloudflare-style `/sse` URLs need it). Connector headers and OAuth (bearer + Authorize-on-401 + one retry via `GetBody`) live in one `RoundTripper` so both transports share them. Cloudflare (and similar) advertise RFC 9207 `iss` but omit it on the callback — fill from the authorize URL origin. A 401 with an empty body is a challenge; do not swallow the OAuth error behind `initialize: http 401: (empty)`. Container is Docker stats (CPU, RAM) plus Start/Stop (`GetContainer`). Create takes a description (shown on the folio). Settings edits name + description via `UpdateBot`. Dangerous: `ResetContainer` is stop+rm (workspace bind stays; Start makes a new box); `DeleteBot` drops the box, the row, and `data/bots/<id>`. Second click, not `confirm()`. Chat is the chats list + thread (`/bots/:id/run/:chatId`). The first title is a short model name from the opening prompt (not the raw message); the sidebar can rename (`RenameChat`). A `chat_title` stream event updates the list and is not shown in the thread. Tools start collapsed. Markdown tables scroll inside the thread (`silo-md-table`); they must not widen the column. `present` of a user path is a folio (not collapsed). `present` of `bot/…` is a collapsed “Looked at …” row. The model must not retype it. A presented png/jpg/webp/gif is attached as pixels on the next completion so the model can see Chromium. Persist fetched blobs from `exec_python` to `/workspace`, then `present` — do not copy them through `write`. Thinking is a spinner only while `thinking_chunk`s are the live tail — a later tool/assistant event (or send end) becomes Thought; leaving `streaming` true keeps the spinner forever. Desktop is the hatch only. A connected worker is **online** (pine lamp), not idle. The CP holds the VNC and Console streams until a viewer attaches, then the Worker dials x11vnc or opens a PTY. Each hatch/console WebSocket gets a viewer ticket; closing an old socket must not clear a newer one (React Strict Mode remounts the hatch). VNC and console are separate lanes — both can stay up. Replacing a worker session must cancel any waiter on the old session. Sign-in must call `setSession` from the response (email + admin) or the session cookie is ignored. `StreamRun` persists every event, replays history, and accepts `after_event_id` so the client can reconnect without duplicates. Chat Stop is `StopRun` (that chat’s live run + worker `CancelCmd`); it is not Stop Bot. Commands carry `run_id`; children get `SILO_RUN_ID`. Parallel runs on one bot are allowed; bot status is derived from remaining running runs and pending approvals. A Docker inspect error is not proof the box is gone — only not-found or a box whose `SILO_BOT_TOKEN` hash ≠ `bots.token_hash` clears the cached ID and `Drop`s. A stopped box keeps its ID. Stop is `docker stop`, not rm. `ResetContainer` is stop+rm and clears the ID. Persist a new token hash only after Create succeeds; a failed recreate plus `live()` adopting the leftover box is what makes the worker hammer 401s. Worker auth misses and rule lookups (no row = catalog default) use `Find`, not `First` — GORM `record not found` is not an error log. Desktop processes are fail-fast: if Xvfb/Openbox/x11vnc/worker dies, the container exits and `unless-stopped` recreates it. Chromium is a dock launcher (`silo-chromium`), not a supervised process. Chrome profile bind is `/home/silo/chrome-profile`. The wrapper is `--enable-low-end-device-mode` + 128MB disk cache + `--load-extension=/opt/silo/ubol`; site isolation stays on — do not launch raw `chromium`. Do not also Chrome-Web-Store force-install uBOL (that duplicates it). Managed policy sets page zoom to ~67% and uBOL lists (ads + cookie/overlay). If `exec_python` mentions Playwright / `chrome_page` and :9222 is down, the worker starts headed `silo-chromium` on `DISPLAY=:1` (not a start.sh child). Connectors are discovered as `import tools` in `exec_python`, not as extra OpenAI tools. Those calls emit `call` / `call_result` and render above the Python fold. Ctrl+C must `Hub.CloseAll` then `http.Server.Close` — never `Shutdown`. The hatch WebSocket is hijacked, so graceful Shutdown waits until a timeout (`context deadline exceeded`) and `signal.NotifyContext` eats extra SIGINTs.

## Two hops

1. **CP ↔ Worker:** ConnectRPC, Worker-initiated, bot token. Concurrent RPCs.
2. **Python ↔ Worker:** HTTP/JSON on `unix:///var/run/silo/worker.sock`.

File tools stay four: `read` (numbered lines, `offset`/`limit`), `write`, `patch` (exactly one `old_text` match), `grep` (`include` glob, capped). Do not add a fifth unless a real loop needs it. `present` is a chat tool on the CP (shows a workspace file in the thread via `browse_file`); it is not a fifth worker file tool. A presented image is also attached as pixels on the next model turn so Chromium work can Perceive → Reason → Act → Verify — do not oneshot cookies+search with guessed labels. Scratch lives in `/workspace/bot`; user-facing files in `/workspace`. `present bot/…` is a collapsed “Looked at …” row, not a folio. The Files tab is a human browser (`mkdir` / `remove` / `put_file` / `browse_file` on the worker, 2 MB). Recreate the box after those worker cmds change.

SOUL and MEMORY live in SQLite (`bots.soul` / `bots.memory`), not on the box. Injected into the system prompt every run. Tools `soul` and `memory` write the DB (no worker hop). Model may write both; Settings can edit them. MEMORY cap is 8000 chars — over that the prompt and the tool tell the model to compact, they do not silent-truncate. ListBots omits the bodies; GetBot/UpdateBot include them.

After create, never `docker exec`, `docker cp`, or a published VNC port.

Container ID in SQLite is the last box. `GetBot`/`ListBots` inspect Docker (and the `silo-{id}` name) and clear a vanished box. `StartBot` starts that ID if it still exists; it creates only when there is no ID or the box is gone. Do not trust a stored ID after a `podman rm`.
