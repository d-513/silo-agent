Silo is one control plane, a Postgres database, and a container engine it makes the Bots' machines on. Pick how much of that you want to manage.

## SiloOS

A bootable image that runs Silo and nothing else: the control plane, its database and Caddy for HTTPS, on rootless Podman. Updates are whole-image and move only forward.

Use it for a dedicated machine or VM. Install media for both architectures are attached to each GitHub Release. On first boot the console shows where Silo is and the first admin's password.

The repository's `images/os/README.md` covers building media, cloud-init and HTTPS.

## One container

The `silo` image holds the control plane with the console compiled in. Postgres (17, with pgvector) is yours to run.

```sh
# Podman (rootless)
podman run -d --name silo --restart unless-stopped \
  --userns=keep-id:uid=1000,gid=1000 --security-opt label=disable \
  -v "$XDG_RUNTIME_DIR/podman/podman.sock:/run/docker.sock" \
  -v /var/lib/silo:/var/lib/silo \
  -p 8080:8080 -p 3479:3479/udp -p 3479:3479/tcp -p 25:2525 \
  -e SILO_DATABASE_URL=postgres://… -e SILO_PUBLIC_URL=https://silo.example.com \
  ghcr.io/d-513/silo:<version>
```

Four things have to be right:

- **The engine's socket** at `/run/docker.sock`. The control plane makes every other container through it.
- **The data directory at the same path as on the host** (`/var/lib/silo` both sides). The engine binds paths under it into the Bots' machines, so a different path or a named volume points every workspace at nothing.
- **Ports**: 8080 for the console and the Bots' workers, 3479 for calls, 25 for mail if you use it. Put TLS in front of 8080.
- **The database** in `SILO_DATABASE_URL`.

Do not name the container `silo-…`: that prefix is for the containers Silo makes.

:::caution
The network filter needs Podman. On Docker, Bots run without it.
:::

## From source

You need Go, pnpm, Podman and `make`.

```sh
make db-up        # Postgres and the dev services
make images       # the Bot's image and the sidecars
make build-cp-ui  # build/bin/silo with the console inside
```

`docs/DEVELOPMENT.md` in the repository has the prerequisites and the dev loop.

## After it starts

1. Sign in as the first admin (`bootstrap.*` in `silo.yaml`, or the generated one on SiloOS).
2. In **Admin → Settings → Models → Providers**, add a provider's key and allow a model.
3. Create a Bot and say hello.
